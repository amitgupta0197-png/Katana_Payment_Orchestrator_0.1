Katana Agent — Install & User Guide

Android capture app for UPI payments · download https://katanapay.co/katana-agent.apk · v3.08
What this app is for: money paid into your payment app (Paytm, Airtel, Google Pay, PhonePe, BharatPe) reaches your Katana dashboard on its own — but the RRN / UTR, the 12-digit reference that proves which payment it was, is only ever shown on the payment app's own screen. The Katana Agent runs on the phone, reads that reference off the screen, and sends it to your dashboard. No typing.

1. What you need

  • An Android phone, version 11 or newer. Use a dedicated phone that stays on and on charge — this is the single biggest factor in how much gets captured.
  • Your payment app installed and logged in to the business account that receives the money.
  • Your merchant code (e.g. MTCI-01) — ask your Katana admin. Captures are stamped with this code, so it decides which account the money is credited to.

2. Install the app

  1. On the phone, open https://katanapay.co/katana-agent.apk in the browser and download it.
  2. Open the downloaded file → allow "Install unknown apps" if prompted → Install.
  3. Android will show a Play Protect warning. Tap More details → Install anyway (or Install without scanning).
The Play Protect warning is expected. It appears for any sideloaded app that reads SMS, which this one does so bank credit alerts are forwarded. It is not a sign that anything is wrong.
Updates install over the top — same signing key, so there is no need to uninstall first, and your settings survive. But see the warning in §3 about what an update does to the screen reader.

3. First-time setup (~5 minutes)

Open Katana Agent and work down the screen.

Step 1 — CONNECTION (do this first)

Scroll to CONNECTION, enter your merchant code, leave Forward alerts on, and tap Save settings. The line must read ✓ verified.

What it saysWhat it means
✓ verifiedThe server recognised the code. This is the only state that captures.
✗ not recognizedThe server does not know this code. Re-check it — a typo sends money to the wrong account, or to nobody.
⚠ can't reach serverThe code may be fine; the phone has no working internet. Check the connection.
(save to verify)Not checked yet. Tap Save settings.
Check the code character by character. A code with a stray space (GUFFI-01 hu) once sat saved for hours looking healthy. The app now refuses to claim it is capturing until the server has confirmed the code — but only you can confirm it is the right one.

Step 2 — PERMISSIONS

Three rows, each with its own button. Each turns into a green tick when granted.

RowButtonWhy it is needed
Bank SMSGrantReads incoming credit SMS.
Notification accessEnableReads bank / UPI-app alerts. Turn Katana Agent on in the system list.
Background activityAllowSet to Unrestricted so Android does not kill the app.

Step 3 — PAYMENT APPS

Turn on the one app you receive money on. Only one can be on at a time — switching one on switches the others off, and the app confirms with "Capturing <app> only".

If you turn everything off, capture pauses and the app says so. Pick the app that actually receives the money — a Paytm/PhonePe mix-up means nothing is ever captured.

Step 4 — RRN CAPTURE

RowSet toWhy
Screen reader (Accessibility)Enable → turn Katana Agent onThis is the capture engine. Without it no RRN can ever be read.
Display over other appsAllowNeeded to read the copied RRN off the clipboard.
Auto-captureOn (default)New payments are found and read automatically — nothing to tap.
Keep screen awakeOn (default)Stops the screen sleeping. Only works while the phone is plugged in.
Re-check the screen reader after every app update. Some phones (OnePlus / OxygenOS, Oppo / ColorOS) silently switch Accessibility off when the app version changes — leaving the phone in the one state where no RRN can be read. The home screen now calls this out as SCREEN READER OFF. After updating, open the app and confirm it says CAPTURING.

The big line at the top says what the phone is actually doing — not merely that the app is installed. Only one of these means money is being captured.

The number, and the four tiles

The large number is payments captured today on this phone, with the time of the last one under it. A count that goes up is the only real proof capture is working. Below it:

5. Daily use

  • Keep the phone on and plugged in.
  • Leave the payment app open on screen — the Open payment app button on the home screen takes you straight there.
  • That is all. New payments are found, opened, read, and sent automatically.
Leaving the Katana Agent screen showing captures nothing. The engine reads the payment app, so while you are looking at the agent, nothing is being read — every indicator stays green. A phone once idled an hour this way. Park it on the payment app.

7. Email channel (BharatPe and emailed receipts)

Under EMAIL CHANNEL (OPTIONAL), connect the Gmail that receives payment emails. For BharatPe this is the only step — the email carries the whole payment, so no screen reading is involved and the phone does not need to sit on the payment app.

  1. Set and save your merchant code first (§3) — the connect button needs it.
  2. Tap Connect Google. Sign in, tap Allow, then come back to the app. The status reads ✓ Connected.
  3. Alternatively, enter the Gmail address and a 16-character app password and tap save (needs IMAP on).

8. Filling one payment on demand ("Get RRN")

On the dashboard, a payment still missing its reference has a Get RRN button. Press it and this phone — as long as it is on, connected, and the payment app is open — re-reads the list and fills that one in. The button clears itself once the reference lands. Nothing to do on the phone.

Under the tiles, the details block shows merchant, device, endpoint and app version — read those out when you report a problem to your Katana admin.

10. Limits worth knowing

  • The payment app must be open on screen for RRN capture. This is how Android accessibility works, and it is why a dedicated always-on phone is recommended. (BharatPe over email is the exception — §7.)
  • Only payments visible on the list can be read. Recent ones are captured automatically; a much older payment needs the list scrolled back to it — ask your Katana admin to run a deep sweep.
  • One phone collects for one merchant code. Two shops need two phones, or the payments land on the wrong account.
  • OTP, PIN and password messages are never forwarded.
  • The payment itself (amount, payer, time) reaches the dashboard on its own — the agent only adds the reference.
