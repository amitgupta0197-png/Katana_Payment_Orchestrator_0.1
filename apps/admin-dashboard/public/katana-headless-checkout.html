Quasi-headless checkout

Open Katana's hosted UPI checkout inside your own app, in a WebView with no browser chrome. The customer picks their UPI app, confirms and pays; your app closes the WebView when Katana says the payment is done.

1. How it works

  1. Your server creates a P2P order (step 2) with your order id as txnid. Katana answers a checkout_url.
  2. Your app opens checkout_url + ?embed=1 in a WebView: no address bar, no navigation buttons.
  3. The checkout shows who is being paid, the amount and the note, and lets the customer choose the UPI app. The app is pre-selected from the customer's own UPI ID when you send customer_vpa.
  4. The customer taps Pay. The checkout opens a UPI app link (upi:// or the app's own scheme). Your app hands that link to the operating system; the WebView must never open it in-frame. NPCI requires the UPI app to own the PIN screen.
  5. The customer approves in the UPI app and comes back. The checkout shows the result, sends your app a message and, with embed=1, navigates to katana://checkout/done?… so your app closes the WebView.
  6. Katana sends your server the signed payment callback. That callback, not the WebView, is the result.

2. Create the order

Use the P2P order API you already use, signed with your Key + Salt exactly as in the main integration guide. Nothing new to sign.

POST https://katanapay.co/api/v1/p2p/order
Content-Type: application/json

{
  "key": "YOUR_KEY",
  "txnid": "ORD-10023",            // your order id: the idempotency key, never reuse it
  "amount": "499",
  "productinfo": "Wallet top-up",
  "customer_vpa": "rahul@ybl",     // optional: the payer's UPI ID, pre-selects their app
  "phone": "9876543210",
  "hash": "…"                      // as in the main guide
}

Answer (extra field for quasi-headless accounts):

{
  "verified": true,
  "flow": "P2P",
  "order": { "id": "3f1c…", "order_id": "ORD-10023", "status": "PENDING", … },
  "pay_url": "https://katanapay.co/pay/3f1c…",
  "checkout_url": "https://katanapay.co/pay/3f1c…/checkout"
}
Retrying the same txnid after a timeout returns the same order and the same checkout_url: a network retry never creates a second payment. A malformed customer_vpa is refused with INVALID_VPA.

3. Open the checkout in a WebView

  • Load checkout_url + "?embed=1". Allow JavaScript and DOM storage.
  • Hide every browser control: no address bar, no back / forward buttons, no title bar showing the URL.
  • Let https://katanapay.co pages load inside the WebView. Any other https address: open it outside, in the system browser.
  • Any other scheme (upi:, phonepe:, paytmmp:, tez:, gpay:, intent:…): cancel the WebView navigation and give the link to the OS. If no app can open it, tell the customer to install a UPI app.
  • katana://checkout/done?id=…&order_id=…&status=…: close the WebView and show your own result screen, then confirm with your server (step 7).
  • When your app comes back to the foreground after the UPI app, keep the WebView as it was: the checkout checks the payment again by itself.

4. Android (Kotlin)

class KatanaCheckoutActivity : AppCompatActivity() {
  private lateinit var web: WebView

  override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    web = WebView(this)
    setContentView(web)                                   // full screen: no toolbar, no URL
    web.settings.javaScriptEnabled = true
    web.settings.domStorageEnabled = true
    web.addJavascriptInterface(Bridge(), "KatanaShell")   // window.KatanaShell.postMessage(json)
    web.webViewClient = object : WebViewClient() {
      override fun shouldOverrideUrlLoading(view: WebView, req: WebResourceRequest): Boolean {
        val uri = req.url
        return when {
          uri.scheme == "https" && uri.host == "katanapay.co" -> false          // stays in the WebView
          uri.scheme == "katana" -> { finishWith(uri.getQueryParameter("status")); true }
          uri.scheme == "intent" -> { openOutside(Intent.parseUri(uri.toString(), Intent.URI_INTENT_SCHEME)); true }
          else -> { openOutside(Intent(Intent.ACTION_VIEW, uri)); true }        // upi:, phonepe:, paytmmp:, https elsewhere
        }
      }
    }
    web.loadUrl(intent.getStringExtra("checkout_url") + "?embed=1")
  }

  private fun openOutside(i: Intent) {
    try { startActivity(i.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)) }
    catch (e: ActivityNotFoundException) { Toast.makeText(this, "Install a UPI app to pay", Toast.LENGTH_LONG).show() }
  }

  private fun finishWith(status: String?) {
    setResult(RESULT_OK, Intent().putExtra("status", status)); finish()
  }

  inner class Bridge {
    @JavascriptInterface fun postMessage(json: String) {
      // {"type":"katana.checkout.done","status":"SUCCESS",…} — optional: log or react early
    }
  }

  override fun onBackPressed() { finishWith("CANCELLED") }    // your app decides; the order stays open until it expires
}

Android 11+ only lets your app see UPI apps it declares. Add to AndroidManifest.xml:

<queries>
  <intent>
    <action android:name="android.intent.action.VIEW" />
    <data android:scheme="upi" />
  </intent>
  <package android:name="com.phonepe.app" />
  <package android:name="net.one97.paytm" />
</queries>

5. iOS (Swift)

final class KatanaCheckoutViewController: UIViewController, WKNavigationDelegate, WKScriptMessageHandler {
  var checkoutURL: URL!
  var onDone: ((String?) -> Void)?
  private var web: WKWebView!

  override func viewDidLoad() {
    super.viewDidLoad()
    let config = WKWebViewConfiguration()
    config.userContentController.add(self, name: "katana")    // window.webkit.messageHandlers.katana
    web = WKWebView(frame: view.bounds, configuration: config)
    web.autoresizingMask = [.flexibleWidth, .flexibleHeight]
    web.navigationDelegate = self
    view.addSubview(web)                                        // present full screen, no navigation bar
    var c = URLComponents(url: checkoutURL, resolvingAgainstBaseURL: false)!
    c.queryItems = (c.queryItems ?? []) + [URLQueryItem(name: "embed", value: "1")]
    web.load(URLRequest(url: c.url!))
  }

  func webView(_ webView: WKWebView, decidePolicyFor action: WKNavigationAction,
               decisionHandler: @escaping (WKNavigationActionPolicy) -> Void) {
    guard let url = action.request.url else { return decisionHandler(.cancel) }
    if url.scheme == "https" && url.host == "katanapay.co" { return decisionHandler(.allow) }
    decisionHandler(.cancel)
    if url.scheme == "katana" {
      let status = URLComponents(url: url, resolvingAgainstBaseURL: false)?.queryItems?.first { $0.name == "status" }?.value
      dismiss(animated: true) { self.onDone?(status) }
      return
    }
    UIApplication.shared.open(url) { opened in                 // upi:, phonepe:, paytmmp:, other https
      if !opened { /* tell the customer to install a UPI app */ }
    }
  }

  func userContentController(_ c: WKUserContentController, didReceive m: WKScriptMessage) {
    // m.body: ["type": "katana.checkout.done", "status": "SUCCESS", …]
  }
}

List the UPI schemes your app may open in Info.plist:

<key>LSApplicationQueriesSchemes</key>
<array><string>upi</string><string>phonepe</string><string>paytmmp</string><string>tez</string></array>

6. Messages from the checkout

The checkout posts each message on every bridge it finds: window.KatanaShell.postMessage(json) (Android), window.webkit.messageHandlers.katana.postMessage(obj) (iOS), window.ReactNativeWebView.postMessage(json) (React Native) and window.parent.postMessage (an iframe).

typeWhenFields
katana.checkout.open_appThe customer tapped Pay and a UPI app link is about to openid, app, url, fallback (a plain upi:// link)
katana.checkout.doneThe payment is finalid, order_id (your txnid), status: SUCCESS / FAILED / EXPIRED

About 2.5 seconds after katana.checkout.done, a checkout opened with embed=1 navigates to katana://checkout/done?id=…&order_id=…&status=….

7. The callback is the truth

The WebView result and the katana:// link are for the screen only: a page or a redirect can be faked on the customer's phone. Credit the customer, or start leg 2, only on Katana's signed payment callback to your server (verify its signature as in the main guide), or on your own server-side status check: GET https://katanapay.co/api/v1/p2p/order/{order id}.

8. Leg 2: pay the receiver

When the callback says the payment succeeded, your server pays the receiver with the payout API you already use (POST /api/v1/payouts/create, a beneficiary with a UPI ID, rail UPI). Send the order's txnid as the payout txnid (payout txnids are 1–40 letters, digits, _ or -): a repeated txnid returns the first payout instead of making a second, so a retried callback never pays twice.

9. Testing

  • Sign the order with your test Key + Salt. The test checkout shows a TEST badge and two buttons, Simulate success and Simulate failure. No money moves.
  • The simulated result sends your server the same signed callback as a real payment, so you can test step 7 and step 8 end to end.
  • Open checkout_url in a phone's normal browser first, then inside your WebView with embed=1, and check that Pay leaves your app for the UPI app and comes back.
